01 · Add to the archive

Register an instrument

Each signed instrument binds its content reference, vectors, and chain position.

A pasted CID is treated as a reference; this prototype does not fetch it or prove that it matches the supplied payload.

The payload SHA-512 digest and raw CIDv1 address are computed locally. Supplying an existing CID overrides the derived address.

Selecting a file reads it locally. Nothing is uploaded unless you explicitly use the local-node upload button. If an existing CID is supplied, the bytes are still included in the signed payload hash.

Only connects to localhost/loopback, only after you click. Kubo’s raw block endpoint accepts blocks up to 2 MiB; larger payloads need a different IPFS import flow. Your Kubo API must allow this page’s origin via CORS. Never expose the Kubo API publicly. Pinata/API-token upload is not configured in this client-only page.

Your private Ed25519 key stays in this browser’s IndexedDB and is not included in exports. Records are stored locally. Uploads occur only when you explicitly send payload bytes to the configured loopback Kubo API; the app does not contact Pinata or retrieve gateway content. It does not provide trusted timestamps, establish identity or legal rights, or enforce a global first-record rule. Keep independent backups of exported records; clearing browser data may remove your key.

About the protocol

An open provenance system

CVP is not a state, a court, or a blockchain. This prototype creates signed records and checks their content addresses, signatures, and chain links. A valid signature proves only that the corresponding private key signed those bytes; it does not independently prove a person’s identity, when the signature was made, factual truth, or legal effect.

Payloads are addressed using CIDv1 with the raw codec and SHA-512 multihash unless an existing CID is supplied. A supplied CID is not fetched or checked against payload bytes. Optional pinning uses Kubo’s local raw-block API only after an explicit click; Pinata credentials and gateway retrieval are not implemented.

For the first instrument, chain.root is the marker SELF to avoid a circular self-CID. Later instruments carry the first instrument’s CID as their root. Signatures cover the canonical unsigned instrument body; the self-CID then commits to that body and its signature.

The dictionary defines meaning. The record preserves meaning. The chain proves history. The archive preserves memory.

Observe → Record → Sign → CID → Archive. Signing runs locally through the browser’s Web Crypto API; no private key is sent to a server.

All is Mind. Mind becomes Definition. Definition becomes Record. Record becomes CID. CID becomes Instrument. Instrument becomes Provenance. Provenance becomes Memory. Memory becomes Archive.

Prototype disclaimer: records are stored in this browser’s local storage and the non-extractable signing key in IndexedDB. Browser data can be changed or cleared; export the archive and retain the browser profile if you need continuity of the signing identity. This page does not provide a global registry, trusted timestamp, legal registration, or guarantee of permanence.
